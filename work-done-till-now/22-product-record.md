# 22. PRODUCT.md and DESIGN.md: the product and design records in mytheus-ui

Status: `DONE` (written on 2026-11-14; committed and pushed in mytheus-ui as `e45d8ea`). Not a plan band. No canon or ADR change: this file records existing product facts and defines no name, number or decision.

## Why

The owner ran `/impeccable init` in mytheus-ui. The Impeccable design tooling reads a `PRODUCT.md` at the repo root before any new surface or redesign work, and the repo had none. It had design documents only (`design.md`, `docs/DESIGN-ONELINE.md`), and those disagreed with each other and with the live copy on one product fact (integrations).

## What landed

- `mytheus-ui/DESIGN.md` (renamed from `design.md` with `git mv`, then rewritten): the design system as the code implements it, in the DESIGN.md format: token frontmatter (colours for light plus the core dark set, five type roles, radii, spacing, component tokens) and the sections Overview, Colors, Typography, Layout, Elevation & Depth, Shapes, Components, Do's and Don'ts. Extracted from `src/app/globals.css`, `src/styles/app-theme.css`, `tailwind.config.ts`, `src/lib/fonts.ts` and `src/components/ui/`, with the rules of `docs/DESIGN-ONELINE.md`.
- `mytheus-ui/.impeccable/design.json`: the sidecar the Impeccable live panel reads: tonal ramps for 44 colours, the three warm shadows, three easings, breakpoints, nine self-contained component snippets and the narrative lifted from `DESIGN.md`. Generated by a throwaway script; the script itself was not kept.
- `mytheus-ui/PRODUCT.md`: platform (`web`), users, product purpose, positioning, operating context, capabilities and constraints, brand commitments, evidence on hand, product principles, accessibility. It holds product truth only: no palette, type or component decisions, which stay in `docs/DESIGN-ONELINE.md`.

## Decisions and why

Three facts were confirmed by the owner in a short interview rather than inferred from the repo:

- Primary user: a team member who sits in many meetings. Managers, workspace admins, platform staff and students are secondary. Why: design decisions need one person to serve first.
- Integrations: Mytheus hosts its own meetings, has several integrations, and has a Chrome extension for meetings held in Chrome on other services such as Google Meet. This overrides the older `design.md` and `LANDING.md` line that Mytheus never integrates with anything. Why: the older docs predate the integrations work (file 16) and the live feature copy already sells Calendar, Slack, Jira and Linear.
- Evidence: none yet. Mytheus is an academic project built to the standard of a complete SaaS and is pre-launch, so customers, testimonials, metrics and certifications are recorded as absent and must not be fabricated.

For `DESIGN.md` the owner chose to overwrite the old `design.md`, which described the retired look (Geist, 40px pills, `ConnectedGraph`, mesh and grain) and whose token values no longer matched the code; the old text stays in git history. The owner left the north star and the component phrase to be picked from the current code: "The One Line" (the repo's own name for the redesign) and "quiet and exact" (dark primary, hairlines, no hover lift).

Where `docs/DESIGN-ONELINE.md` and the code disagree, `DESIGN.md` follows the code: display type is Syne on marketing and auth, Inter Tight in the app, and Newsreader on the marketing home only (the contract still says Newsreader everywhere), and app text is upright, never italic.

Everything else in `PRODUCT.md` comes from `CLAUDE.md`, `docs/DESIGN-ONELINE.md`, `docs/PAGES.md` and `src/lib/marketing/features.ts`.

## Verified

- `PRODUCT.md` exists at the mytheus-ui root and carries the `impeccable:product-schema 1` marker. No code changed, so no lint, typecheck, test or build was run.

- `LANDING.md` in mytheus-ui still says "no integrations" and still points at `design.md`; it was left as it is.
- `docs/DESIGN-ONELINE.md` still names Newsreader as the display face and lists `design.md` among the older docs it outranks. Not edited.
- `DESIGN.md` was not checked against rendered pages in a browser; it was extracted from source only. The marketing hero size and the call room's own stylesheets (`src/styles/meeting*.css`) are not documented in it.
- Impeccable's optional setup was not done: no `.impeccable/config.json` build path was recorded and live mode was not configured.
