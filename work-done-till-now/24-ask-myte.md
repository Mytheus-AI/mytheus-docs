# 24. Ask Myte

Not a plan band ([ADR-0047](../adr/0047-ask-myte.md), [ADR-0049](../adr/0049-ask-myte-v2.md)). Status: **DONE WITH GAPS** (v1 live in production since 2026-11-14; v2 merged and deploying 2026-11-14; the open items are listed under Open gaps).

One place to ask your Myte anything across Mytheus: the `/ask` page, a sheet on every app page (`Cmd+J` / `Ctrl+J`) and entry points on the sidebar, Your Myte, Home, meeting and decision pages, the meeting room and the command palette. Answers stream with numbered citations, in the person's own Myte character (its plush, name, personality, instructions and voice). Every write is a proposal the person confirms. v2 adds asking a teammate's Myte, Myte reaching out first, seven more actions, memory, routines, voice mode and attached text files, plus the reliability items below.

No dependency was added. Fallback if a device shows buffering: an XHR `onprogress` reader behind the same `streamFetch` seam (documented, not built).

## Deviations, and why

- The loop lives in rag-service, not agent-runtime-service: rag-service already verifies Clerk sessions, owns "ask" and is routed by the gateway; agent-runtime has no HTTP surface in production.
- Tools are reached through bff `POST /mcp` as the asker, so Myte can never see more than the person can, and every tool also serves Claude.
- No thinking: thinking tokens cost too much for chat (owner). `between_tools` is Sonnet 5.5's "off" in a tool conversation.
- Peer answers are drafted in the recipient's session and reviewed before sending, and routines run on the next visit: Myte has no session of its own, and running as a person while they are signed out was not built.
- Slack posts copy the text and open Slack: there is no public Slack post route.
- The new bff tools read in-process rather than over HTTP, because personal access tokens are refused on `/users`, `/notifications` and `/api/v1/listening`.
- `mytheus-mobile` runs the web route's orchestration on the device. ADR-0047 D8 names the `mytheus-ui` server as the persister; the phone has no server, and a second server for one client would be new backend surface. The steps, keys and fallbacks are the same, rag-service stays a non-writer and core-api persists, and no name, route, table or event is new, so canon is unchanged. ADR-0047 D8 is amended (2026-11-16) to say a client without a server performs that role itself.
- `mytheus-mobile` paths: the plan put the ports under `src/lib/ask-myte/` (mirroring the web path, beside the other pure libs) and the network orchestration in `src/api/ask-myte.ts` (so all REST still goes through `src/api/client.ts`). The workflow's task text mentioned `src/ask-myte/`; the approved plan's layout was kept.
- `mytheus-mobile` differences from the web hook: proposal marks and their stored states, feedback, voice and attachments are not ported; a single `useOpenMyteThread` fetch replaces a `useMyteThread(id)` query hook (the sheet only needs to open a thread once); delete asks for a confirm instead of a Toast with Undo, because the server deletes for good and has nothing to undo to. `asPersonality` checks a list of the five presets instead of `value in PERSONALITY_LABEL` (the label map is not on mobile, and `in` would accept an inherited key).

- `mytheus-mobile` never produces the D10 `offline` state. The web reads `navigator.onLine`; the phone has no connectivity signal without a new native module (`@react-native-community/netinfo` or `expo-network`), which means a new development build and a runtime-version bump for one line of copy. A dropped network shows `unavailable` ("I couldn't answer just now. Nothing was lost. Try again in a moment."), which offers Retry and keeps what streamed, so only the word "offline" is lost. Revisit when a native release adds a connectivity module for another reason. Recorded in ADR-0047 D10 (amended 2026-11-16) and mobile `system.md` N27.
- `mytheus-mobile` draws only the session's way out of `failureCopy` ("Sign in again", which signs out because the phone has no page to reload); the admin ones open web-only Workspace pages (mobile N3), so `isAdmin` is never passed.
