## Live gap list

Ordered by what blocks the most downstream work. Closed since 2026-07-27: `rbac_grants` and `audit_logs` exist with RLS; `organizations.clerk_org_id` is built and resolved through `libs/shared/org_resolver.py`; every HTTP service has its routes; CI runs in `mytheus-backend` and `mytheus-events`; and [threat-model/stride.md](../threat-model/stride.md) is up to date with the fixes.

1. **No end-to-end run exists.** Both clients are wired to the contract and both build clean, but nothing has been exercised against a live Clerk instance and a deployed gateway together. Section 3.10's two acceptance checks are specifically the ones outstanding: two different-tenant users seeing disjoint data, and a network capture confirming the browser never sends `org_id`. The property is structurally enforced (no parameter for it exists in either client) and unit-tested on mobile, but "structurally enforced" is not "observed".
2. **No generated TS client in either client repo.** **Unblocked 2026-08-28**, not yet built. The reason Plan 1-2 gave for not building one - "the OpenAPI specs are hand-written rather than emitted from the FastAPI app, so generating from them would encode drift rather than prevent it" - no longer holds: they are emitted now, and the emitted documents carry the RFC 7807 error shape, the bearer scheme and the `Idempotency-Key` parameter that the hand-written ones never did. Both clients still keep a small hand-written types file as the single place drift can hide. **Two findings from scoping this on 2026-08-29, before any code was written.** First, only ONE client repo has a client to replace: `mytheus-mobile` has no API layer at all (gap 32). Second, `mytheus-ui`'s hand-written `ErrorCode` union has already drifted, and in the direction that matters: it lists 15 of the 17 codes the server emits, missing `CONSENT_REQUIRED` and `NOT_A_PARTICIPANT`, which are exactly the two outcomes its own `livekit-token` route comments say it must keep distinct. Generating today would also REGRESS dashboard typing, because `services/bff/dashboard.py` declares `items: list[dict[str, Any]]`, so the emitted `Arm.items` is weaker than the hand-written `Arm<T>`; typing that Pydantic model is a prerequisite, and it is entirely inside `mytheus-backend`.

36. **All three `mytheus-intelligence` consumers would have processed exactly one message and then stopped.** `BaseConsumer.run_forever` called `asyncio.run(process_raw(...))` per message, creating and closing a fresh event loop each time, while the async clients each worker holds are built once at startup; `redis.asyncio` binds its connection pool to the first loop, so message 2 raised `RuntimeError: Event loop is closed`, the exception escaped the poll loop, and the consumer died with exactly one offset committed. Silent by construction, since that committed offset means a restart processes one more. It affected `embedding-service`, `ingestion-service` and `search-service` alike, and it was invisible because every test called `process_raw` directly inside a single loop while the method's own docstring recorded that it was "not exercised in unit tests". **Found and fixed 2026-08-29** by the first sustained-load run, which drained one message in ten minutes; the fix is one event loop for the consumer's lifetime. **The lesson generalizes past this bug:** a component whose tests all call its inner method and never its entrypoint has an untested entrypoint, whatever the coverage number says.

38. **A schema change reached the repo and was never registered, and no gate could see it.** The registered `transcript-chunks-value` was version 1, without the `redacted` field that `mytheus-events/schemas/transcript-chunks/v1.avsc` has carried since the Plan 3-4 work. Avro serializes to the REGISTERED schema, so `redacted` was silently dropped from every message, and `search-service`'s "a chunk arriving with `redacted=true` is never indexed here" check (`services/search_service/consumer.py` line 92) was **dead code in practice: redacted transcript text was being written into the Postgres FTS index.** Found 2026-08-29 as a failing `test_redacted_chunk_is_not_indexed`, which had been failing for the same reason before this session and is fixed by running `make register` (the provisioning path B4 built), after which the subject is version 2 and the suite is green. **The gate that should have caught it cannot:** `check-compatibility` passed throughout, because adding a defaulted field IS backward compatible - compatibility says nothing about whether the registry matches the repo. The fix is a `register --check` mode that fails when any local schema differs from its registered latest, wired into CI beside the compatibility gate.
