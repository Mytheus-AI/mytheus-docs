\section{Proactive Agent: Shifting LLM Agents from Reactive Responses to Active Assistance}
\paperhead{Proactive Agent: Shifting LLM Agents from Reactive Responses to Active Assistance}{Yaxi Lu, Shenzhi Yang, Cheng Qian, Guirong Chen, Qinyu Luo et al.}{arXiv preprint, 2024}{https://arxiv.org/abs/2410.12361}{arXiv API id\_list=2410.12361, title match 1.00}

\subsection{What the paper does}

Most LLM agents are reactive: they wait for an instruction, then execute. This paper asks when an agent should speak \emph{without} being asked, inferring a task from observation alone. It formalises this as $P_t=f_\theta(E_t,A_t,S_t)$ over environmental events, user activities and environment state, where the prediction $P_t$ may legitimately be \emph{nothing}; the user returns a binary $R_t$, and an auxiliary $N_t$ records whether help was truly needed, so correct silence scores as success under $\max_\theta \mathrm{E}[R_t]$. Making silence a scored action rather than the absence of one is the conceptual move.

The method is data-driven, not prompt-engineered, and yields two artefacts: a reward model trained on human accept/reject labels that substitutes for user judgement as an automatic evaluator, and ProactiveBench, 6,790 events synthesised by an LLM-driven gym for fine-tuning open-weight models.

\subsection{How the method works}

An ActivityWatch-based monitor captures real keyboard and mouse operations, visited pages and development tools; records are merged into coherent segments and rewritten by a language model into natural-language events. GPT-4o expands annotator-supplied seed jobs into scenarios across coding, writing and daily life, populated with entities, statuses and a simulated clock. Three components then run in a closed loop. The \textbf{Environment Gym} generates $E_{t+1}$ from history plus sampled example events and maintains state, GPT-4o updating entity properties and the clock into $S_{t+1}$. The \textbf{Proactive Agent} emits $P_t$ or abstains. The \textbf{User Agent} simulates activities and decides acceptance: an accepted task executes inside the gym and spawns further events, while a rejection simply lets the gym advance. For the human-grounded portion, five predictions with minimum total cosine distance are picked per trace and labelled by three annotators as \emph{accept}, \emph{reject} or \emph{reject all}, giving 1,760 entries. LLaMA-3.1-8B-Instruct is fine-tuned as a binary classifier on a 1,640/120 split (batch 32, lr 1e-5, Adam, 3 epochs) to become the reward model; it and Qwen2-7B-Instruct are then fine-tuned on the 6,790-event set and tested at temperature 0.

\subsection{What it reports}

The reward model reaches 91.80\% F1 against the annotators' majority vote (precision 90.32\%, recall 93.33\%), the annotators agreeing among themselves at over 91.67\%. The breakdown matters more: on False-Detection cases it agrees 100.00\% of the time while prompted GPT-4o agrees 0.00\%, so an off-the-shelf LLM judge cannot recognise a false alarm. On the 233-event test split GPT-4o scores 64.60\% F1 at 51.85\% false alarm; fine-tuning lifts LLaMA-3.1-8B from 55.06\% to 66.25\% and Qwen2-7B from 60.74\% to 66.47\%, the best reported. Recall is near-saturated almost everywhere (roughly 98\% to 100\%) while precision sits near 50\%: the whole difficulty is staying quiet. Allowing three candidates at once (pred@3) raises GPT-4o to 77.72\% F1 at 36.44\% false alarm, whereas reward-model feedback in a refinement turn cuts false alarms but collapses recall (GPT-4o to 56.00\% F1). \subsection{How Mytheus uses this}
\begin{takeaway}
Cite Table 3 as the honest external anchor for \texttt{ProactiveAgent}: even after task-specific fine-tuning the best model reaches only 66.47\% F1 at 50.22\% false alarm, so roughly half of unsolicited offers are unwanted. That is the empirical case for NO SILENT COMMITS and the 0.7 gate, and it obliges the golden-set harness to report the conflict detector's false-positive rate as a headline metric beside conflict precision. Then \emph{build} the reward model: every candidate already passes a confirm-or-dismiss step, so accept/reject labels accrue at zero annotation cost, and 1,640 sufficed here. Two adaptations are forced. Per-tenant isolation forbids a single global judge, so train a tenant-agnostic base and calibrate the 0.7 and 0.4 thresholds per tenant, never pooling raw confirmations across \texttt{org\_id}. And adopt pred@3: let the workload and missing-stakeholder detectors offer up to three candidates per window, which alone cut GPT-4o's false alarm from 51.85\% to 36.44\%. Keep this judge off the \texttt{ContextGapAgent} path, since a multi-turn draft, feedback, refine loop plus an 8B classifier cannot survive the 1.5\,s p95 peer round trip, though it fits \texttt{ProactiveAgent}'s p95 under 4\,s budget. Finally, the 100.00\% versus 0.00\% False-Detection gap warns against scoring conflict false positives in CI with a prompted LLM judge.
\end{takeaway}

\subsection{Limitations and what it leaves open}
\begin{itemize}[leftmargin=*, itemsep=1pt, topsep=2pt]
  \item Both training and the headline table are scored by a simulated User Agent and an 8B reward model, never live humans; user-centric evaluation is deferred to future work, so the reported F1 is a proxy judged by a proxy.
  \item Observation is single-user desktop telemetry from one machine: no multi-party event stream, no notion that one event matters to one person and not another, no agent-to-agent communication.
  \item Acceptance $R_t$ is strictly binary: no calibrated confidence, no middle band between speaking and silence, and precision is never plotted against a threshold, so nothing indicates where a cut-off such as 0.7 belongs.
  \item No latency or cost accounting appears: inference times, token counts and the added cost of pred@3 and the refinement loop go unreported, and the best configurations are multi-turn by construction.
  \item The reward model is a single global judge fitted to a majority vote of three annotators, with no per-user or per-tenant mechanism and no test of whether one trace should be accepted by one role and rejected by another.
\end{itemize}
