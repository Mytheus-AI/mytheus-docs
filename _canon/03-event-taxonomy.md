# NEXUS Canonical Event Taxonomy

The single naming authority for every NEXUS Redpanda topic — its Avro value schema, producer/consumer services, tenant partition key, retention, and delivery/idempotency rule — distilled verbatim from [Event-Driven Architecture](../07-event-architecture.md).

## Topic catalog

All 22 topics (9 PDF-original + 13 SaaS-added; `agent-feedback` is the thirteenth, [ADR-0040](../adr/0040-polish-program.md)). Partition key is `org_id` (the tenant UUID string) on 20 of the 22 topics. `transcript-chunks` and `agent-stream` are the exception: their partition key is the composite `{org_id}:{meeting_id}` ([ADR-0017](../adr/0017-transcript-chunks-composite-partition-key.md)) — it preserves within-meeting speech ordering while letting a hot enterprise tenant spread across partitions. `org_id` remains present and non-nullable in the envelope header on every topic, including these two; it is the tenant key and the leading component of their composite key even though it is no longer the whole key. Every other topic keeps `org_id` alone as its partition key. A paired `<topic>.dlq` (14-day retention) exists for every topic. Delivery is **at-least-once, idempotent in effect**: every consumer dedupes via the durable `inbox` table plus Redis cache `nexus:{org_id}:dedupe:{topic}:{consumer_group}:{idempotency_key}` (24h TTL, one key per consumer group, ADR-0031 D6); explicit `idempotency_key` formulas are given where [07 §6.3](../07-event-architecture.md) defines one.

## Avro envelope and Schema Registry

Every event value opens with the shared `EventEnvelopeHeader` (namespace `io.nexus.events`) then a topic-specific `payload`. Locked across all 22 topics. Frozen header fields:

| Field | Type | Role |
|---|---|---|
| `event_id` | `string` (uuid) | Unique per emitted event; distinct from `idempotency_key`. |
| `idempotency_key` | `string` | Business dedupe key; stable across producer retries of the same fact. |
| `org_id` | `string` (uuid) | Tenant root; RLS/cell scoping anchor; the Kafka partition key on 20 of 22 topics, and the leading component of the `{org_id}:{meeting_id}` composite key on `transcript-chunks` and `agent-stream` (see Partition key column above). |
| `schema_version` | `int` (default 1) | Producer's payload schema version (observability; Registry enforces compat independently). |
| `producer` | `string` | Owning service name (kebab-case, from the Service Catalog). |
| `occurred_at` | `long` (timestamp-micros) | When the fact happened (UTC); not enqueue time. |
| `correlation_id` | `["null","string"]` (default null) | Ties a causal chain across topics. |
| `causation_id` | `["null","string"]` (default null) | `event_id` of the direct cause; null for root events. |

- **Subject naming:** `{topic}-value` — one subject per topic. No key schemas; the partition key is the raw `org_id` UUID string.
- **Compatibility:** **BACKWARD**. Allowed: add a field with a default; remove a field that had a default; widen via union with `null` + default; append enum symbols with a default. Forbidden: add a required field without a default; remove a non-defaulted field; rename; narrow a type. Header field order is frozen by convention.
- **Enforcement:** CI `check-compatibility` against the registered subject gates every producer image build.
